Minicut Shot Detector

Splits a mini cut into its shots — one file per shot, in the format you gave it, with every cut checked against the source.

Choose a source below and Inspect it. Then Analyse it, mark where each shot starts by playing through it, and split.

What this version handles

  • Hard cuts only. Dissolves, fades and wipes are not detected as edits.
  • Constant frame rate only. Variable frame rate sources are refused — re-encode to constant frame rate first.
  • Masking is reported, not applied. Letterboxing is measured and shown, but shots are always cut at full frame.
  • h264 and h265 only. Shots come back in the codec and container they went in as, re-encoded once so cuts land on the exact frame.

      Works on any folder of single-shot files, whether or not the Splitter made them. Load your production knowledge and a shot list, point it at the folder, and review what it proposes.

      What this version handles

      • A model does the describing. Unlike the Splitter, this cannot be deterministic — the same shot can be described differently twice, which is why you review every row before anything is renamed.
      • It proposes, you decide. A shot it cannot place is left unnamed rather than guessed at, and nothing is renamed until you approve it.
      • One folder at a time. Shots are read from a single directory, not gathered from several.
      • Renaming appends. The original filename is kept and the shot number added to it, so a file can always be traced back to the mini cut it came from.

          Installing what you need
          Connecting a command line tool

          The Identifier talks to a model by running a command you already have and reading what it prints. Anything that takes a prompt and answers in text will work, so you are not waiting on us to support a particular tool.

          Pick Custom command… in the Models panel and type the command as you would in a terminal. The prompt is sent in on standard input, so most tools need only their non-interactive flag:

          Claude Code
          claude -p — already a preset.
          Kiro CLI
          kiro-cli chat --no-interactive --trust-all-tools {prompt} — already a preset, and what a new machine starts on. --no-interactive is Kiro's equivalent of claude -p, and it takes the prompt as an argument rather than on standard input, which is why the preset carries {prompt}. Without a trust flag it waits for a tool approval it cannot show and appears to hang; --trust-tools=read,grep narrows that if you would rather not trust everything. The interactive UI flags --classic and --tui do nothing here, because non-interactive mode has no UI to pick. Image support is unconfirmed — press Test before relying on it for the vision model.
          Another agentic CLI
          Whatever runs it non-interactively and prints the reply, for example mytool chat --quiet. If it needs the prompt as an argument rather than on standard input, write {prompt} where it should go.
          Sending frames to it
          Only the vision model gets images. Write {images} for one argument per frame, or --image={image} to repeat a flag for each one.

          Press Test after any change. It runs the command once and shows you the reply, or says exactly what went wrong.
